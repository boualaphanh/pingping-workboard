## What the prototype already settled

Do not re-litigate these while building; they were decided with the user on 2026-09-21.

1. **Parent navigation is three tabs — Map · Growth · Family.** The map is the home screen; alerts
   are an icon on it. There is no separate Home dashboard and no Safety tab (PR-7, benchmark F-1).
2. **Two themes, one key set.** `parent` and `kids` are two instantiations of the same tokens, which
   is the `product ∈ {parent, kids}` flavor dimension from Architecture v0.7 §1. Forking the design
   system is forbidden (Engineering Handbook §7).
3. **Kids `onPrimary` is dark green, not white.** White on the lime is 3.52:1 and fails WCAG AA.
4. **`statusStale` and `statusOffline` are different colours.** Feature Breakdown A1 requires a
   parent to tell "the phone is off" from "location permission was revoked".
5. **A5 Loud Signal is in MVP-S1** (PR-8) — screens P34 and K09.
6. **Four states on every screen**, with exactly four documented exceptions: P01, P06, K03, K09.

## Suggested build order

The backend is ahead of the app: `pingping-api` has 46 routes through S1b (identity, family, device
pairing, location, SOS, SSE) on `feature/s1b-device-location-sos`. Build the app against what
exists, and **trace one capability end to end before planning on top of it** (Mobile Handbook §14.6
— the project has already been bitten by a middleware that verified tokens no endpoint issued).

1. **Repo scaffold** — one repo, two apps, `product × env` flavors, per Architecture v0.7 §1.
2. **Theme and l10n first.** Drop in `pp_colors.dart` and the two ARB files; prove both flavors and
   both themes render before any feature screen exists.
3. **The generated Dart client** from the contract (CN-1). Do not hand-write models.
4. **E1 auth (P02) → E3 add child (P04) → B5 pairing (P05, K01).** Nothing else works until a
   device is paired.
5. **A1 map (P10)** — the home screen, against `GET /v1/families/:id/children/:id/location/latest`.
6. **A4 SOS (K02, K03, P09)** and the SSE stream.
7. **A5 loud signal (P34, K09)**, A11 battery, B6 device health (P20).
8. The rest of the manifest.

## Two things the API cannot answer yet

- **The map label "At school · 1 h 36 min".** `locationLatestView` returns `lat, lng, accuracyM,
  source, batteryPct, recordedAt, ageSec` — no resolved place, no dwell, no silent-mode flag. The
  screens are drawn assuming all three. They arrive with A2 in Sprint S2 (benchmark F-3); until
  then the label has to degrade to "Updated {n} min ago".
- **Push.** `NotifyPort` still has only a console adapter, so an SOS reaches a parent only through
  an open SSE stream. A4.4 needs the real adapter before any of this is trustworthy in the field.

## Gates that apply from the first commit

`pp-standards-brief` before writing code, then: four states per screen, no colour or spacing literal
in a feature file, no hardcoded user-facing string, 48 dp touch targets, text scaling to 200 %,
golden tests in both languages and both themes, analyzer clean. `pp-dependency-gate` before adding
any pub.dev package.
